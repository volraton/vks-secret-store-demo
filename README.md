# VKS Secret Store Demo

A practical VMware Cloud Foundation 9 / VKS lab demonstrating:

- VCF 9 vSphere Supervisor
- VCF Secret Store Service with OpenBao as the secret system of record
- VKS workload cluster
- Argo CD GitOps
- External Secrets integration on the VKS side
- Flask sample application
- PostgreSQL
- Secret synchronization into a Kubernetes Secret
- Secret rotation
- GitOps application updates

> **Lab scope:** this repository is designed for a private/lab VCF 9 environment. Version-specific Secret Store integration objects must match the VCF/VKS release actually installed in the environment.

# Architecture

```text
                         VMware Cloud Foundation 9
                                      |
                         +------------+------------+
                         |                         |
                 vSphere Supervisor              VKS
                         |                         |
              +----------+----------+          Argo CD
              |                     |              |
       Secret Store Service        |          GitHub repo
              |                     |              |
            OpenBao                |              |
              |                    |              |
        demo-db secret             |              |
              |                    |              |
              +-----------> ExternalSecret <------+
                              |
                         db-credentials
                              |
                    +---------+---------+
                    |                   |
                 Flask              PostgreSQL
                    |
                    +---- DB connection
```

## Separation of responsibilities

```text
GitHub / Argo CD
    |
    +-- application manifests
    +-- image reference
    +-- Kubernetes configuration

VCF Secret Store Service
    |
    +-- database username
    +-- database password
    +-- secret lifecycle

VKS
    |
    +-- Flask workload
    +-- PostgreSQL workload
    +-- Kubernetes Secret generated by the secret integration
```

The database password is **not** stored in Git.

# Prerequisites

You need:

- VMware Cloud Foundation 9.x
- vSphere Supervisor enabled
- A vSphere Namespace with suitable storage/network configuration
- VCF Secret Store Service enabled for the namespace
- A VKS workload cluster
- Argo CD available in the VKS cluster
- The VKS Secret Store / external-secret integration appropriate to your installed release
- A container registry reachable by VKS nodes
- `kubectl` and the VMware `kubectl-vsphere` plugin

For the exact Secret Store Service and VKS add-on versions, use the VCF interoperability matrix and the versions displayed in your environment. Do not mix manifests from another VCF/VKS release.

# 1. Verify the Supervisor

Login to the Supervisor:

```bash
kubectl vsphere login \
  --server <SUPERVISOR-IP> \
  --vsphere-username administrator@vsphere.local \
  --insecure-skip-tls-verify
```

Check the context:

```bash
kubectl config get-contexts
kubectl config current-context
```

Check namespaces:

```bash
kubectl get namespaces
```

Check Secret Store related workloads/objects:

```bash
kubectl get pods -A | grep -Ei 'secret|bao'
kubectl get svc -A | grep -Ei 'secret|bao'
kubectl get crd | grep -Ei 'secret|bao'
```

The exact namespace and object names are release dependent.

---

# 2. Install or enable VCF Secret Store Service

In the vSphere Client, use the Supervisor Services area and install/enable the **Secret Store Service** version compatible with the VCF 9 environment.

Conceptually:

```text
vSphere Client
  -> Workload Management
  -> Supervisor
  -> Services
  -> Secret Store Service
```

If the service is already installed, do not reinstall it. Verify that it is healthy first.

If the service requires a `values.yaml`, use the storage class/storage policy from your own Supervisor environment:

```bash
kubectl get storageclass
```

Do not assume a storage class name from another environment.

```text
Namespace: demo
```

# 4. Create the remote secret

Create a logical secret in the VCF Secret Store Service:

```text
Name: demo-db

username = demo
password = VMware123!
```

The important point is that this value lives in the VCF Secret Store, not in Git.

The expected logical secret path/name used by this repository is:

```text
demo-db
```

Verify that the secret exists and that the identity used by the workload integration has permission to read it.

---

# 5. Verify Secret Store before deploying VKS workloads

Do this before deploying the application.

Check the Supervisor service health and verify that the `demo-db` secret can be accessed through the supported VCF Secret Store interface.

If the Secret Store is not healthy, stop here and fix it before continuing.

This separation makes troubleshooting much easier:

```text
Secret Store problem     -> fix Supervisor
VKS problem              -> fix VKS/add-on
Argo CD problem           -> fix GitOps
Application problem       -> fix Flask/PostgreSQL
```

# 7. Verify the VKS Secret Store integration

This repository uses an external-secret synchronization pattern. The exact provider/CRD integration must match the Secret Store Service and VKS version installed in your environment.

Start by discovering what is actually installed:

```bash
kubectl get crd | grep -Ei 'secret|external'
kubectl get pods -A | grep -Ei 'secret|external'
kubectl get addon -A | grep -i secret
kubectl get addonrelease -A | grep -i secret
```

If External Secrets Operator is part of the selected integration, verify it:

```bash
kubectl get pods -A | grep -i external-secrets
kubectl get crd | grep external-secrets
```

The repository expects the Kubernetes-side store to be represented as:

```text
ClusterSecretStore/vcf-secret-store
```

and the remote secret as:

```text
demo-db
```

**Important:** `ClusterSecretStore/vcf-secret-store` is an integration contract used by this sample. Its provider configuration is intentionally not hard-coded here because the correct provider/API configuration depends on the Secret Store integration exposed by the installed VCF/VKS release.

Do not replace this with a generic HashiCorp Vault Helm deployment unless that is explicitly what you intend to demo.

# 8. Check the repository's ExternalSecret

The sample contains:

```yaml
apiVersion: external-secrets.io/v1
kind: ExternalSecret
metadata:
  name: db-credentials
  namespace: demo
spec:
  refreshInterval: 1m
  secretStoreRef:
    kind: ClusterSecretStore
    name: vcf-secret-store
  target:
    name: db-credentials
    creationPolicy: Owner
  data:
    - secretKey: username
      remoteRef:
        key: demo-db
        property: username
    - secretKey: password
      remoteRef:
        key: demo-db
        property: password
```

The result should be:

```text
VCF Secret Store
      |
      | demo-db
      v
ClusterSecretStore
      |
      v
ExternalSecret
      |
      v
Kubernetes Secret
  db-credentials
```

# 18. Test secret rotation

The purpose of this test is to show that the application credential is independent of Git.

Change the password in VCF Secret Store Service from:

```text
VMware123!
```

to a new lab value, for example:

```text

```

Wait for the configured synchronization interval and check:




```text
      |

      |

      |
```

# 19. Troubleshooting

## Argo CD is OutOfSync

```bash
kubectl get applications -n argocd
kubectl describe application vks-secret-demo -n argocd
```

Check that Argo CD can reach:

```text
https://github.com/volraton/vks-secret-store-demo.git
```

## ExternalSecret is not Ready

```bash
kubectl describe externalsecret db-credentials -n demo
kubectl get events -n demo --sort-by=.lastTimestamp
```

Then verify:

```bash
kubectl get crd | grep -Ei 'external|secret'
kubectl get pods -A | grep -Ei 'external|secret'
```

Most commonly this indicates that `ClusterSecretStore/vcf-secret-store` has not been created or its provider configuration does not match the installed VCF/VKS Secret Store integration.

## PostgreSQL is not Ready

```bash
kubectl get pods -n demo
kubectl describe pod -l app=postgres -n demo
kubectl logs deployment/postgres -n demo
```

Check that `db-credentials` exists before debugging PostgreSQL itself.

## Flask cannot connect to PostgreSQL

```bash
kubectl logs deployment/secret-demo -n demo
kubectl get svc postgres -n demo
kubectl get endpoints postgres -n demo
```

Verify that PostgreSQL is Ready first.

## Secret rotation does not affect the running application

This is expected when the secret is injected into environment variables. Updating the Kubernetes Secret does not change the environment of an already-running process.

Restart the workload:

```bash
kubectl -n demo rollout restart deployment/secret-demo
```

# 20. Security notes

This is a demonstration repository.

The public README contains the disposable lab credential:

```text
VMware123!
```

Treat it as compromised and non-secret.

For production:

- Generate a unique random password.
- Never commit the password to Git.
- Never put it in a Dockerfile or image layer.
- Never put it in Helm values committed to Git.
- Use the VCF Secret Store Service as the source of truth.
- Use least-privilege policies for secret access.
- Use TLS and valid certificates.
- Rotate credentials regularly.
- Avoid printing secret values in logs.

# 21. Final demo story

This sample is intended to demonstrate four independent planes:

```text
             APPLICATION PLANE
                    |
                 Flask
                    |
               PostgreSQL

             GITOPS PLANE
                    |
                 GitHub
                    |
                 Argo CD
                    |
                   VKS

             SECRET PLANE
                    |
          VCF Secret Store
                    |
                 OpenBao

             INFRASTRUCTURE
                    |
                 VCF 9
                    |
            vSphere Supervisor
```

The key message for the demo is:

> **Argo CD manages what the application is. VCF Secret Store manages what the application must keep secret. VKS runs the workload.**
